# 假模型（--demo）

## 1. 这个功能对用户是什么

假模型是一个**不联网、不花钱、也不聪明**的替身。它的作用是让你在还没配好接口密钥的时候，就能把整条链路亲手走一遍，看清楚「我敲一句话，最后变成了什么文件」。

它也用在自动化测试里——测试要快、要稳定、不能每次跑都花钱。

**它不会骗你**：用 `--demo` 时屏幕上会明说「这次用的是假模型」，处理图片时它会在 OCR 位置直接写「假模型没有真的读这张图」。

## 2. 一次调用的完整路径

```
life add "…" --demo
  ↓
cli.add() 发现 --demo，把 用假模型=True 传下去
  ↓
extract.抽取() → _调一次()
  ↓
fake_model.假抽取(原文)   ← 一堆 if 规则，不联网
  ↓
返回和真模型一模一样的 JSON 文本
  ↓
后面的解析、校验、写 markdown、建索引，和真模型**完全一样**
```

## 3. 关键代码在哪

```
life/fake_model.py::假抽取()   文字 → 假条目
life/fake_model.py::假看图()   图片 → 假 OCR（明说是假的）
life/fake_model.py::_猜分钟()  「4 小时」→ 240
life/fake_model.py::_找技术词() 靠一张二十来个词的表格找锚点
life/fake_model.py::_猜档位()   证据档位 0~3 的关键词规则
```

## 4. 为什么这么设计

最容易被做错的决定是：**造一个「看起来特别真」的假模型，还是造一个一眼能看出是假的？**

「看起来真」很有诱惑力——截图给别人看特别漂亮。但它被否掉了：一旦假的足够像真的，你自己分不清哪条记录是 AI 真抽的、哪条是假模型糊的，等配好密钥时你会以为抽取已经验证过了。

所以规则是：**假就明说假。** OCR 位置直接写「假模型没有真的读这张图」，屏幕上每次调用都提示一句。

另一个决定：假模型的输出**必须走同一条下游管道**（同样的解析、校验、写文件）。如果假模型直接吐出最终文件，那它就没法验证下游代码，等于白做。

## 5. 已知限制

- 它只认关键词，不懂语义。它会把「今天很累」判成情感记录，但分不清「累」和「累并快乐着」。
- 中文锚点靠一张手写的小词表（二十来个词）。表里没有的技术词它找不出来，于是校验会判定「没有锚点」，那条记录会被标成 `needs_review`。
- 它不会真的读图片，也不能用它的结果判断抽取质量。**要验证抽取好不好，必须配密钥跑真模型。**
- `--demo` 和真模型混着用时，产物看起来一样，只有屏幕提示能区分。记录文件里没有「这条是假模型抽的」标记——这是待改进项。

# 导出（life export）：把记录变成能交出去的东西

## 1. 这个功能对用户是什么

你说你要什么，它给你一个**能直接用的文件**：

```powershell
life export "我要应聘机器人相关的工作，帮我生成一份简历"
life export "我要发微博关于我的人生，帮我概括一下"
life export "面试要用，帮我写个自我介绍"
life export "给导师的周报"
life export "把这三年的技术经历整理成一份给朋友看的文档"
```

- **前四个走内置模板**：简历 / 微博 / 自我介绍 / 周报。每个模板都有一份「指导文档」，
  写清了格式、该写什么、别写什么（简历那份是对着网上的简历规范整理的，文档末尾有来源）。
- **认不出模板就用「通用」**：由模型按你的要求自己决定写成什么样，指导文档只守底线。
- 文件落在 `vault/导出/20261126-1547-简历.md`，路径会打在屏幕上。

一句话概括它和「提问」的分工：**提问给的是回答，导出给的是能发出去的东西。**

## 2. 一次调用的完整路径

```
life export "我要应聘机器人相关的工作，帮我生成一份简历"
  ↓
① export.选模板(要求)        → 简历（关键词命中；认不出就通用）
② export.挑素材(要求)        → 三路混：
                               · 按这句话检索到的相关记录
                               · 模板声明的「必带」关键词命中的记录
                                 （简历：在读 / GPA / 本科 / 四级 / 证书…——这些往往躺在「接触」档）
                               · 档位 ≥ 2 的记录（拿得出手的，按档位和时间排）
                               上限 26 条，私密记录一条都不进
③ export.组装素材()          → 底色 + 目标 + 主题 + 记录清单（带日期、档位、锚点、卡点）+ 你的原话
④ llm.调用("dialogue", prompts/export_<模板>.md, 素材)
  ↓
⑤ export.可疑数字(正文, 素材) → 正文里有、素材里没有的数字（防编造的机械检查）
  ↓
⑥ 写 vault/导出/<时间>-<模板>.md，可疑数字写在文件最前面
```

`--dry-run` 只跑 ①②，把挑出来的素材列在屏幕上，**不调模型、不写文件**——用来判断「挑得对不对」。

## 3. 关键代码在哪

```
life/export.py::模板们          内置模板表：指导文档、后缀、关键词、必带关键词
life/export.py::选模板()        从你的一句话里认模板
life/export.py::挑素材()        三路混素材（相关 / 必带 / 档位高的）
life/export.py::组装素材()      给模型的原材料
life/export.py::导出()          主流程：素材 → 指导文档 → 模型 → 写文件
life/export.py::可疑数字()      编造数字的机械检查
life/prompts/export_简历.md     简历的指导文档（含来源）
life/prompts/export_微博.md · export_自我介绍.md · export_周报.md · export_通用.md
life/cli.py::export            命令本身（--template / --max / --dry-run / --out）
```

## 4. 为什么这么设计

**① 为什么要有「指导文档」这一层，而不是一句话丢给模型？**

因为模型默认会写出一份**没人会看的简历**：自我评价、性格开朗、爱好广泛、四个页面。
指导文档把它按住：一页、动词开头、倒序、有结果写结果、别写自我评价。
这也是用户的第一条要求——「你要先在网上查找简历格式和要求」——落下来的地方。

**② 为什么简历敢用，微博也敢用，却不敢让它随便编？**

导出物一旦发出去就代表你本人。所以有两条硬规矩写死在指导文档里：
**不许编经历，不许编数字**。再加一道机械检查：正文里出现、素材里没有的数字，
一律列在文件最前面让你核。它很笨（抓不到「精通」这种软性吹牛），但「3 项专利」「提升 40%」跑不掉。

**③ 为什么素材要「档位高的」和「必带关键词」两条路？**

只用检索：简历里最该出现的往往是半年前那个「独立做完」的项目，它和「应聘机器人相关的工作」
这句话在字面上未必像（没有向量路，字面不像就是捞不到）。
只用档位：学历、绩点、四六级这些必需信息往往躺在「接触」档，会被漏掉——
实测第一版简历的「教育背景」全是「（待补：专业）」。
所以三条路一起走，加起来才是「一份简历需要的材料」。

**④ 为什么内置模板而不是让用户自己写模板？**

写模板要先懂提示词，那是给做工具的人用的。内置四个覆盖了绝大多数真实场景
（求职 / 发社交 / 口头介绍 / 汇报），剩下的交给通用模板。
**模板是「有默认答案」，不是「必须先选答案」。**

**⑤ 被否掉的替代方案**

- **做成网页上的一页**：这次没做（CLI 先走通）。导出是低频、要改文件、要另存的动作，
  命令行反而顺手；等用得多了再加页面。
- **导出成 PDF / docx**：需要额外依赖（本仓库不许引第三方渲染库）。先给 markdown，
  你自己粘到 Word 里排。**能省掉的依赖就省掉。**
- **让模型自己决定挑哪些记录**：把几千条塞进去它挑不准，而且一次几万 token。

## 5. 已知限制

- **只有命令行，没有网页入口**。想导出得敲 `life export "…"`。
- **模板只有四个**（简历 / 微博 / 自我介绍 / 周报）+ 通用。想要「作品集」「演讲稿」得用通用模板，或者加一个。
- **不给 PDF / docx**：输出是 markdown 或 txt，排版要你自己来。
- **没有向量路**（只用一个本机接口），所以「按意思相关的记录」靠全文 + 档位，字面不像的捞不到。
- **数字检查只管数字**：编出来的「精通 C++」「带领五人团队」这种文字它抓不到，发出去前必须自己读一遍。
- **一次一份，不能追问**：不满意就改要求重跑一次。想「再简化一点」得重新导出。
- **私密记录永远不进素材**，所以只有私密记录能支撑的导出会得到一堆「（记录里没有）」。
- 导出文件写在 `vault/导出/`，**不会被 `life tidy` 清理**，也不会自动归档——自己删。

# 回顾（life review）

## 1. 这个功能对用户是什么

一段时间之后，它给你一份回顾：这段时间做了什么、证据分布变了多少、情绪怎么走的、有没有晋升、以及**一个**下周的建议。

```powershell
life review --week                                  # 最近 7 天，打印到屏幕
life review --quarter --html --out 回顾.html         # 本季度，生成单文件网页
```

五块内容固定：**这段时间做了什么 / 证据分布变化 / 情绪 / 晋升事件 / 下周一个建议（只给一个）**。

## 2. 一次调用的完整路径

```
life review --week
  ↓
① 定区间：--week 是最近 7 天；--quarter 是自然季度（本季度第一天到今天）
② 数数据（不靠模型）：这段时间的 entry、按档位分布、上一段同样长度的分布、
   总投入分钟数、带情绪的 valence 序列、changelog 里这段时间的晋升事件
③ 交给模型写「这段日子怎么过的」，system = life/prompts/review.md
     禁止：空泛鼓励、复述原话、三条以上建议、编数字、百分比
④ 拼输出：
     markdown = 头部数据 + 模型正文
     HTML     = 同一份内容 + 内联 CSS + 手写 SVG 情绪曲线（单文件、无外链）
⑤ 模型调不动 → 照样输出，只少了那段话，并注明「这次没连上模型」
```

## 3. 关键代码在哪

```
life/review.py::区间()          周 / 季度的日期范围
life/review.py::收集()          数数据：分布、上一段对比、情绪点、晋升事件
life/review.py::生成()          主流程
life/review.py::_用模型写()     调模型；失败时不阻断
life/review.py::_拼markdown()   markdown 输出
life/review.py::_拼HTML()       单文件 HTML（CSS 内联、SVG 手画）
life/review.py::_简易markdown转HTML()  只认 ## 和 - ，不引 markdown 库
life/prompts/review.md          回顾的写法规矩
life/cli.py::review             命令本身（--week / --quarter / --html / --out）
```

## 4. 为什么这么设计

**① 为什么数据全部由代码数，只有一段话交给模型？**
因为数字错一次，整份回顾就不可信了。条数、档位分布、平均情绪这些都是 `COUNT`/`AVG`，不会胡说；模型只负责「这段日子怎么过的」这一件它擅长的事。**分工是：算数归代码，说话归模型。**

**② 为什么模型挂了也要出回顾？**
回顾是低频动作（一周一次、一季度一次）。如果因为断网就什么都看不到，用户下次就不跑了。所以模型失败只降级掉「那一段话」，数据照出——这和录入那边「先落盘」是同一种设计：**能自己算出来的东西，绝不依赖网络。**

**③ 为什么 HTML 也要单文件、不引框架？**
和 `life board` 同一个理由：三年后、换台电脑、网断着，双击还能打开。`--html` 只是把同一份内容换了个皮。

## 5. 已知限制

- 「下周一个建议」是模型写的，**没有代码校验它只给了一条**（prompt 里要求了，但不保证）。
- 情绪曲线只画有 `valence` 的记录；都在 0 附近时曲线是条直线，看不出东西。
- 上一段对比用的是「同样长度的前一段」，不是「上个季度」——所以 `--week` 比的是前 7 天，`--quarter` 比的是上一季度。
- `--html` 里的 markdown 转换只认 `##`、`###` 和 `-` 列表，加粗、链接不会渲染。
- 晋升事件是从 `changelog.md` 里按日期前缀筛的，你手改日期格式就筛不到。

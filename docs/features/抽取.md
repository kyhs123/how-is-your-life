# 抽取（一段话 → 一张档案卡）

## 1. 这个功能对用户是什么

你随口写的一句话，通常带着一堆没用的东西：「今天又在搞那个 oauth 的登录，烦死了，文档写得跟屎一样……」

三个月后你再看这句，能用的信息很少。抽取做的事，是把它压成这样：

> **接通 OAuth 登录，卡点为 state 参数签名**
> 情绪：-0.5（不太好）｜ 强度 0.7 ｜ 触发：文档不清 ｜ 原话：「文档写得跟屎一样」

短，但技术名、卡点、情绪、原话全留着。判断标准只有一句：**三个月后看到它，能不能立刻讲出一个具体细节。**

## 2. 一次调用的完整路径

```
vault/inbox/<id>.json（原话）
  ↓
① 算出这次的「钥匙」：prompt 版本（prompt 文件内容的指纹）+ 模型名
② --private → 完全不调模型，原话截断 60 字，标 needs_review，结束
③ 查缓存：内容指纹 + prompt 版本 + 模型名 三样全对上 → 直接用上次结果，不再花钱
④ 读 life/prompts/extract.md 当系统提示（prompt 是纯文本，没硬编码在代码里）
⑤ 调模型。结构化输出按三级降级试：
     第 1 级 json_schema  把字段结构直接交给接口
     第 2 级 json_object  只要求返回一个 JSON 对象
     第 3 级 纯文本       从回复里抠 ```json 代码块，或第一个 { 到最后一个 }
⑥ 解析 JSON
⑦ 校验：did 非空且 ≤60 字、part 合法、是 record 就必须有至少一个锚点
⑧ 不过 → 把错误原话回喂给模型，再试一次（总共两次）
⑨ 还不过 → 兜底：原话截断存下来，status = needs_review，绝不静默丢弃
⑩ 过了 → 规范化：补默认值、砍长度、把 valence 夹进 -1~1、level 夹进 0~3
⑪ 返回 entries（一般是 1 条；一段话讲了三件事就是 3 条）
```

## 3. 关键代码在哪

```
life/extract.py::抽取()          主流程：缓存 → 调模型 → 解析 → 校验 → 重试 → 兜底
life/extract.py::校验条目()      哪些问题真的不能用（宁可报错也不放过去）
life/extract.py::_解析()         三级降级里「从乱七八糟的回复中抠出 JSON」
life/extract.py::_规整()         能修的毛病直接修，不必劳烦模型重来
life/extract.py::prompt版本()    prompt 内容的指纹，改了 prompt 缓存自动失效
life/extract.py::取缓存结果()    按 (内容指纹, prompt 版本, 模型) 取上次的结果
life/llm.py::调用()              真正发 HTTP 请求，三级降级在这里执行
life/prompts/extract.md          抽取规则 + 正反例（few-shot）
life/prompts/extract_image.md    图片版的抽取规则
```

## 4. 为什么这么设计

最容易被做错的决定是：**怎么让模型交出能直接用的字段？**

最常见也最坑的做法是在 prompt 末尾写一句「请用 JSON 格式输出」，然后指望它听话。它十次里有三次会多写一句「好的，结果如下：」，你的程序当场崩。这个方案被否掉了。

现在用的是 **结构化输出 + 客户端校验 + 降级重试**：

- 优先让接口自己按 schema 约束格式（`json_schema`），这是唯一有保证的方式；
- 接口不支持就退一步，再不行就从文本里抠——**三级都写了，哪一级能用就用哪一级**；
- 拿到结果不信它，逐字段校验。不合格就把错误说明白点回给模型重来一次；
- 两次都不行，宁可标 `needs_review` 让人来看，也不假装成功或者丢掉。

「宁可留一条要人看，也不要丢一条」——因为记录产品里，丢一条的代价远大于多一条待办。

## 5. 已知限制与实测结果

**已经在真接口上跑过了**（本机转发接口 + `deepseek-v4.1-flash`）：

- 结构化输出走到**第 1 级 `json_schema` 就成功**，不需要降级
- 20 条真实输入 → 23 条记录（有两句话被正确地拆成了多条）
- `did` 全部 ≤60 字（最长 48 字），没有一条为空
- 乱码、只打一个标点、空字符串：都不崩溃，原话保留、标 `needs_review`
- 图片：一张终端截图，OCR 把 traceback 逐行抄全了，原图按设计删掉，正确拆成两条（bug 一条、跑测试一条）

仍然存在的限制：

- **模型不是完全确定的**（温度 0.2，不是 0）。同样的输入两次可能给不同结果，所以「重复提交不产生两条」靠的是内容指纹，不是模型。
- 一段话该拆几条，全靠模型判断。实测「绕过反爬；学 Docker；修完 bug」被拆成 3 条，其中第三条信息其实很稀薄。
- `level`（证据档位）是模型按关键词猜的，可能偏高。看到「上线」就给 2 档，但上线的东西可能是个玩具。
- 模型原本会用旁观者口气转述（「表达很累，未说具体原因」），已在 prompt 里明令禁止并复验通过。**以后再换模型或改 prompt，这类问题可能回来**，验收时要专门盯这一条。
- 改了 `prompts/extract.md` 任何一个字，缓存全失效，旧内容都要重抽（故意的）。
- 图片的 160px 缩略图没做（§5.5 标的是可选）。
- 长截图（几千字的代码截图）可能超出 `max_tokens: 2000`，被截断时 OCR 就不完整了。没实测过边界。

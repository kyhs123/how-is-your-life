# 网页界面（life server）

> 施工图在 [`docs/WEBUI.md`](../WEBUI.md)。这份文档是「这个功能在用户眼里是什么 + 怎么实现的」。

## 1. 这个功能对用户是什么

一条命令，在浏览器里打开一个**只属于你本机**的页面。它是这个工具的主界面：

| 页面 | 你能做什么 |
|---|---|
| **今天** | 写一句话记下来（可选「这是感受」「只存本地」）；看最近七天写了什么 |
| **记录** | 翻全部记录，按月分组，按「做过什么/想去哪/感受」和证据档位筛选 |
| **单条** | 看一条的全部字段（锚点、卡点、原话、情绪），改那句话/档位/结果/状态 |
| **提问** | 输一句话，它翻出相关旧记录并回答；也可以只看它翻到了什么 |
| **目标** | 立目标、改目标、看证据卡（几条记录、各档几条、拿得出手的、还缺什么） |
| **章节** | 看靠证据晋升出来的主线，以及它名下有哪些记录 |
| **画像** | 看最近一份季度画像（假设清单 + 相对上季度的变化） |
| **回顾** | 看最近七天的数据摘要 |
| **设置** | 数据目录、用的什么模型、记录条数、累计 token |

```powershell
.\.venv\Scripts\life.exe server --open
```

**它就是主界面，但没取代命令行**：`settle` / `promote` / `portrait` / `review` 这四个要调模型、要等几十秒到两分钟的活，仍然在命令行做（页面上会告诉你该敲哪条）。

## 2. 一次调用的完整路径

```
life server --port 8770
  ↓
① 起一个 ThreadingHTTPServer，只绑 127.0.0.1
② 生成一个一次性令牌，写进每页的 <meta> 和每个表单的隐藏字段
  ↓
浏览器 GET /
  ↓
③ 校验 Host（必须 127.0.0.1:端口 / localhost:端口）
④ 取数据：待确认条数、最近七天、总数统计
⑤ pages.今天(...) 拼出 HTML → 发回去
  ↓
在「记一条」里写一句话，点「记下来」→ POST /add
  ↓
⑥ 校验 Origin → 校验令牌 → 读表单
⑦ recorder.记录一条(...)：算指纹 → 查重 → 写 inbox（★这里之后内容就不会丢）
   → 调模型抽取 → 写 vault/now/…md → 建索引 → 删 inbox
⑧ 303 跳回 /（PRG，刷新不会重复提交）
⑨ 首页重新渲染，新那条出现在「最近七天」里
  ↓
点某条记录 → GET /entries/<id> → 改完 POST → 校验 → store.改条目字段 → 写回索引 → 303
```

```
浏览器 ──HTTP──> server.py（路由 + 安全） ──> pages.py（只拼 HTML）
                        │
                        ├──> recorder.py（记一条：CLI 和网页共用）
                        ├──> store.py（条目读写、改字段、改状态）
                        ├──> goal.py（目标与证据）
                        └──> retrieve.py / ask.py（提问）
```

## 3. 关键代码在哪

```
life/server.py::处理器            路由 + 三道安全校验 + 取数据
life/server.py::_全部条目()        页面用的数据（**含私密记录**，会打标）
life/server.py::_记录视图()        筛选 + 分页 + 按月分组
life/server.py::_提问()            GET /ask：召回 → 可选调模型
life/server.py::_记一条()          POST /add
life/server.py::_改条目()          POST /entries/<id>
life/pages.py::布局()             导航 + 样式 + 页脚（所有页面共用）
life/pages.py::今天/记录列表/单条/提问/目标*/章节*/只读文本页/设置
life/pages.py::样式()             整套 CSS（一处定义，无外部资源）
life/recorder.py::记录一条()      记一条的完整链路（CLI 与网页共用同一份）
life/store.py::改条目字段()        只允许改 did/level/outcome/status
life/store.py::检查记录id()        挡住 `../` 这类路径穿越
```

## 4. 为什么这么设计

**① 为什么把「记一条」放在首页最上面？**
第一版只做了目标和「确认待确认」，被项目所有者一句话点破：「记录人生才是主要任务」。这是对的——如果打开页面不能立刻写一句话，这个页面就只是个配置面板。所以主表单必须在首屏、不需要滚动、不需要点进二级页面。

**② 为什么写操作全部复用命令行那套函数？**
`recorder.记录一条` 是 CLI 和网页**共用的同一份实现**。如果网页另写一套「先抽取再落盘」，两边的顺序、去重、图片处理早晚会不一致，而这种不一致极难发现。原则：**一个动作只允许有一份实现。**

**③ 为什么 `settle`/`portrait`/`review` 不在页面上跑？**
它们要调模型 30 秒~2 分钟。虽然服务能并发，但一个表单提交等两分钟，用户会以为卡死；要真正做好得引入后台任务队列 + 进度轮询，那已经超出「本机小工具」的范围。所以页面上只读展示结果，并给出可复制的命令——**承认边界，比做一个半吊子的进度条好。**

**④ 为什么私密记录在页面上可见，却不出现在提问里？**
页面上看得见，是因为这是你自己的电脑、你自己的记录，藏起来只会让人以为丢了。不出现在提问/画像/回顾里，是因为那些动作会把内容发给模型（§8 的承诺）。**「给你看」和「发出去」是两件事，不能混为一谈。**

## 5. 已知限制

- **图片上传没做**。网页里只能记文字；`life add --image` 仍然走命令行（`multipart` 要手写解析，边界和安全容易出错，留到 M3）。
- **不能删除记录**。设计里没有「删除」这个概念，要删请直接删 `.md` 文件——那需要你明确地做一件事。
- 不能批量改、不能改 `private` 标记、不能改正文（正文目前等于 `did`）。
- `settle`/`promote`/`portrait`/`review` 不在页面上跑（原因见上）。
- `/ask` 会同步等 5~20 秒，期间浏览器只转圈、没有进度提示。
- 没有登录；只绑 `127.0.0.1`，能坐在这个电脑前的人就是主人。多人共用电脑时别开着它离开。
- 只绑 IPv4 回环，用 `localhost` 可能解析到 `::1` 导致打不开——请直接用 `127.0.0.1`。
- 记录上千条时列表靠分页（50 条/页），但每次请求仍会读全表统计；没做缓存。

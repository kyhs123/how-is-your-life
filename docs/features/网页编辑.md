# 网页编辑（life server）

## 1. 这个功能对用户是什么

一条命令，在浏览器里打开一个只属于你本机的页面。里面能**做两件事**：

1. **新建 / 修改目标**（标题、期限、为什么、截止、状态）
2. **把「待确认」的记录一键确认**（抽取时模型没把握的那些，标着 `needs_review`）

```powershell
life server --open        # 打开 http://127.0.0.1:8770/
```

**只做这两件。** 不做批量编辑、不做富文本、不做拖拽排序、不能删记录、不能改正文。

改完立刻生效——因为它改的就是 `vault/` 里那些 markdown 文件本身，没有「同步到云端」这一步。

## 2. 一次调用的完整路径

```
life server --port 8770
  ↓
① 只绑 127.0.0.1（局域网里别的机器连不上）
② 生成一个一次性令牌，写进每个页面的 <meta> 和每个表单的隐藏字段
  ↓
浏览器 GET /
  ↓
③ 校验 Host 头（必须是 127.0.0.1:端口 或 localhost:端口）→ 不对就 403
④ 从索引里取：待确认的记录（status=needs_review 且非私密）+ 全部目标
⑤ 渲染一张页面（CSS 内联，不引任何外部资源）
  ↓
点「＋ 新建目标」→ GET /goal/new → 填表 → POST /goal/new
  ↓
⑥ 校验 Host、校验 Origin/Referer、校验令牌
⑦ goal.建目标() → 写 vault/goals/<标题>.md + 写索引
⑧ 303 跳回首页（POST 之后一定要重定向，否则刷新会重复提交）
  ↓
点「就是这样，确认」→ POST /entry/<id>/settle
  ↓
⑨ store.改条目状态() → 重写那个 .md 的 status 行 → 写回索引 → 303 跳回
```

## 3. 关键代码在哪

```
life/server.py::启动()          起服务器，绑 127.0.0.1
life/server.py::造服务器()      造服务器（测试用，端口可传 0）
life/server.py::处理器          路由 + 三道安全校验
life/server.py::_首页()         待确认记录 + 目标列表
life/server.py::_目标表单()     新建/编辑共用一张表单
life/server.py::_建目标/_改目标/_确认记录   三个动作
life/server.py::_样式()         全部 CSS（内联，不引外部资源）
life/goal.py::更新目标()        改目标的字段（id 和文件名不变）
life/store.py::改条目状态()     改一条记录的状态并重写文件
life/cli.py::server            命令本身
```

## 4. 为什么这么设计

**① 为什么用标准库 `http.server`，不用 Flask / FastAPI？**
因为一个依赖都不加。`pip install -e .` 之后就能跑，不用管版本冲突、不用管 ASGI/WSGI、不用管生产部署——它本来就只服务一个人、只在本机、一次跑几分钟。用框架的唯一好处是写 CRUD 更快，而这里只有三个动作。

**② 为什么只做两件事？**
设计 §10 里写死了第一版的范围。理由是：**写操作会直接改用户的真实人生记录，风险比只读高一个量级**。先只做「新建/改目标」和「确认状态」这两件最安全的事——它们改的是元信息，不碰记录正文。改正文、删记录这些留到以后，等这套流程被用熟了再说。

**③ 为什么本地工具还要校验 Host 和令牌？**
两个真实存在的攻击：

- **DNS rebinding**：别人做一个域名解析到 `127.0.0.1`，骗你浏览器去访问，你的浏览器就会把「本机服务」当成那个域名的服务，攻击者就能读到你的记录。所以只认 `Host` 是 `127.0.0.1`/`localhost` 的请求。
- **CSRF**：你打开着某个恶意网页，它偷偷向 `127.0.0.1:8770` 提交一个表单（改你的目标）。所以每个表单带一次性令牌，并且校验 `Origin`。

这两条都不是「以防万一」，是本地 Web 工具的必备项。

**④ 为什么 POST 之后要 303 跳转？**
不然你按一下刷新，浏览器会再提交一次表单——目标被建两遍。这个模式叫 PRG（Post/Redirect/Get）。

## 5. 已知限制

- **不能改记录正文、不能删记录、不能批量操作**——第一版范围就到这。
- 没有登录密码。它只绑 `127.0.0.1`，别的机器连不上，所以默认「能坐在这个电脑前的人就是主人」。如果你的电脑多人共用，别开着它离开。
- 只绑 IPv4 回环（`127.0.0.1`），`[::1]` 没绑——用 `localhost` 访问时如果解析到 IPv6 会连不上，请直接用 `127.0.0.1`。
- 令牌在进程启动时生成，重启浏览器没事，**重启服务器**就要刷新页面。
- 页面没有 JS，所有交互靠表单提交 + 整页刷新。所以不会有「实时保存」。
- 私密记录（`--private`）不出现在网页上（有测试盯着）。

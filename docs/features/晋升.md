# 固化与晋升（life settle / life promote）

## 1. 这个功能对用户是什么

当下日记了很多条，散的。这个功能做一件很克制的事：**发现「这件事你一直在做」，然后问你一句「要不要把它记成一条主线」。**

它绝不自己决定。流程永远是：**系统提名 → 你确认 → 生效。**

```
life settle --week     # 归纳本周记录，够条件的写成提名
life promote           # 一条条问你：要 / 不要

  ── OAuth state 参数通了 ────────────────
     摘要：11 月 OAuth 终于打通，关键在 state 参数要用同一把密钥签
     依据：跨 9 月、10 月、11 月、共 4 条记录
     涉及 4 条记录，最高 3 档
     要把它升成章节吗 [y/N]:
```

## 2. 一次调用的完整路径

```
life settle --week
  ↓
① 取最近 7 天的记录（不含私密）
② 太少（<2 条）就不折腾模型，直接说「先不用固化」
③ 把这几条发给模型，让它找「主题」：标题 + 关键词 + 涉及哪几条 + 有没有产出物
④ 用主题的关键词**回连全库**，把以前同类的记录也串进来（见下面「为什么」）
⑤ 检查 §3.2 的三个条件，必须同时满足：
     重复：跨 ≥2 个不同月份
     产出：有 level ≥2 或带链接的记录
     厚度：≥3 条独立记录
⑥ 满足 → 写一行提名到 vault/changelog.md，并把提名详情存进 vault/缓存/提名/
   不满足 → 打印「暂不提名」和缺哪一条
  ↓
life promote
  ↓
⑦ 列出待确认提名，一条条问 y/n
⑧ 要 → 建 vault/chapters/<标题>.md，把涉及记录的 chapter 字段回填，
       往 changelog 写「晋升 …」+「依据：…」
   不要 → 标记「已拒绝」，以后同一主题不再提
```

## 3. 关键代码在哪

```
life/promote.py::提名()         settle 的全部逻辑
life/promote.py::检查条件()     §3.2 那三条的机器版
life/promote.py::_回连()        用关键词把历史记录串起来（下一步的关键）
life/promote.py::确认()         建章节 + 回填 chapter + 写日志
life/promote.py::拒绝()         标记拒绝，以后不再提
life/promote.py::待确认提名()   从 vault/缓存/提名/ 里读
life/prompts/settle.md          找主题的 prompt（要求给出 keywords）
life/cli.py::settle/promote     命令本身
```

## 4. 为什么这么设计

**① 为什么绝不自动晋升？**
设计里有一句很重的话：「我以为你重视这个」经常是错的，**错判一次用户就不再信任系统**。所以流程固定为提名 → 确认。宁可让你多按一次 `y`，也不要让系统替你说「这才是你的人生主线」。

**② 为什么 settle 只看本周，检查条件却要看全库？**
这是设计文档里两处对不上的地方，我按意图做了拼接：

- §4.6 说 settle **每周跑一次、读本周记录**；
- §3.2 却要求晋升必须「同一主题在 **≥2 个不同月份**出现」。

只看一周，永远不可能跨两个月。所以分工是：**本周记录用来「发现」主题，主题里的关键词用来把历史记录「串」起来**，条件检查跑在串完之后的全部记录上。这样每周跑一次也能攒出跨月的证据。

**③ 为什么拒绝过的就不再提？**
因为反复提同一件你已经否掉的事，等于不尊重你上一次的判断。设计 §4.6 的验收项里明写了这条。

## 5. 已知限制

- **依赖模型判断「哪些记录是同一个主题」**。它可能把两件事捏成一件，也可能把一条线拆成两条。关键词回连是补救措施，不是保证。
- 条件里的「产出物」判定偏宽：只要有 level ≥2 或一个链接就算有产出，没校验那个链接还能不能打开。
- 章节 → 底色（§3.2 的第二条晋升路线）**没有实现**：它需要「跨 ≥2 个完整章节 + 迁移证据」，现在章节都还是零。`vault/core.md` 目前只能手改。
- 提名详情存在 `vault/缓存/提名/` 里，那是可删的缓存。删了之后 `life promote` 就找不到待确认的提名（changelog 里的历史记录还在）。这是为了让 changelog 只放「人话记录」、不放机器数据。
- `life promote` 是逐条交互。想一次性全确认（比如补跑历史数据）才用 `--yes`，它不看内容直接全升。

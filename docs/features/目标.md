# 目标（life goal）

## 1. 这个功能对用户是什么

你写下「想学完后端基础」，然后照常记事。过一阵回头看这个目标，它不会给你一个「完成 62%」的数字——那玩意儿是骗人的。

它给你的是**证据**：

```
## 学完后端基础    2026-09 → 现在
42 条记录 ｜ 投入 ~65h ｜ 最近 3 天活跃

证据分布
  能讲     1 条   给同学讲了 JWT 刷新
  产出     5 条   api-server（repo）、部署上线、N+1 优化
  复现    12 条
  接触    24 条

能拿出手的：
  · 给同学讲了 JWT 刷新（能讲）
  · 部署上线（产出）
```

看这张卡，你自己就知道「我是真的会了，还是只是在门口转」。面试官问「你会什么」的时候，你答的就是这张卡。

```powershell
life goal add "学完后端基础" --horizon term --why "想自己能做一个完整的网站"
life goal list
life goal show 1
life goal done 1
life goal stop 1 --reason "发现更想做前端"
```

### 在目标页上直接记一条（网页）

打开 `/goals/<目标>`，页面底下就是这个目标自己的「记一条」：

- 写完点「记到这个目标里」→ 这条记录的 `goal` 字段**直接写成目标标题**，不问模型
- 记完回到同一页，上面立刻多一条证据
- 写错了（比如把「什么时候」填成未来）→ **留在这一页**告诉你为什么，不会把你甩回首页
- 传文件（简历、截图、笔记）也行，走的是和首页一样的上传链路

命令行上等价于：

```powershell
life add "投了三家实习，第二家做完笔试" --goal "找到实习"
```

### 问老师（目标页上的对话框）

同一个页面上还有一个「问老师」：一个对话框，加三个一键问题（「我该从哪开始？」「接下来一周做什么？」「我卡住了，帮我拆一下」）。

它的人设是**专业、有规划、像老师**（`life/prompts/goal_chat.md`），而且有一条硬规矩：

> **它只看这个目标名下的证据。** 别的目标的事、最近几天的杂事、私密记录，都不进它的上下文。

所以它能说出这种话：

> 你现在三条都是接触档：看教程、跑通了示例。这不算做过。
> 这周只做一件事：把它改成能给别人看的东西——README 写清楚它在解决什么问题，跑起来截两张图。

对话存在 `vault/dialogue/<目标 id>.jsonl`，一个目标一个文件，关掉页面也还在，下次进来接着聊。

## 2. 一次调用的完整路径

```
life goal add "学完后端基础" --horizon term --why "…"
  ↓
① 检查有没有重名目标（有就报错，不让立第二个一样的）
② 组装字段：id / title / horizon / why / started / due / status / progress_mode / parent
③ 写 vault/goals/学完后端基础.md（markdown + 开头那段键值）
④ 同时写进索引的 goals 表
  ↓
life goal show 1
  ↓
⑤ 从索引里取出全部非私密记录
⑥ 挑出 goal 字段指向这个目标的那些（这就是「证据」）
⑦ 按证据档分组数数、按档位举 2~3 个例子、算出总投入时间
⑧ 渲染成文字卡片
```

```
vault/goals/<标题>.md ──┐
                        ├─→ goal.算证据() ─→ 一张卡片（纯文字）
索引里的全部记录 ────────┘   （按 entry.goal 字段关联）
```

在目标页上记一条，走的是**同一条录入链路**，只多一步：

```
POST /add（表单里多两个隐藏字段：goal=目标标题、back=/goals/<id>）
  ↓
recorder.记录一条(…, 目标="找到实习")
  ↓
写 inbox → 抽取（照常）→ 写 now/<月>/<id>.md
     ↓ 这里：条目.goal 直接改成「找到实习」（模型猜的不算）
  ↓
303 跳回 /goals/<id> → 页面重新算证据 → 新的一条出现在上面
```

问老师走另一条路（同步等十来秒，和 `life ask` 一样）：

```
POST /goals/<id>/chat（token + q）
  ↓
goalchat.问(标识, 问题)
  ├─ goal.算证据(目标)              ← 这个目标名下有几条、各档几条、卡在哪
  ├─ goalchat.组装上下文()          ← 目标字段 + 证据清单 + 底色 + 最近 3 轮对话
  ├─ llm.调用("dialogue", …)        ← 人设来自 prompts/goal_chat.md
  └─ 追加一行到 vault/dialogue/<id>.jsonl
  ↓
303 跳回 /goals/<id> → 页面上多一轮问答
```

## 3. 关键代码在哪

```
life/goal.py::建目标()      立目标（查重 + 写文件 + 写索引）
life/goal.py::找目标()      按编号/名字/前缀找，省得你打全名
life/goal.py::关联条目()    哪些记录算这个目标的证据
life/goal.py::算证据()      数条数、数档位、算时长
life/goal.py::渲染卡片()    输出那张卡
life/goal.py::改状态()      done / stop（stop 会把原因写进文件）
life/cli.py::goal_add/list/show/done/stop   命令本身
life/cli.py::add(--goal)                    命令行上记到某个目标
life/pages.py::目标详情()    网页：证据卡 + 页面底下的「记一条」表单
life/server.py::_记一条()    读表单里的 goal/back；记完回到原来那一页
life/server.py::_安全的回退() 回跳地址只认站内路径
life/recorder.py::抽取并保存() 有「目标」时把它写进每一条的 goal 字段
life/goalchat.py::问()          目标页的「问老师」：上下文 + 调模型 + 落盘
life/goalchat.py::组装上下文()   只放这个目标的东西（证据、底色、最近三轮对话）
life/goalchat.py::读对话()      从 vault/dialogue/<id>.jsonl 读回来（坏行跳过）
life/prompts/goal_chat.md       人设与硬规矩（一次只给一个下一步、不给百分比…）
```

## 4. 为什么这么设计

最容易被做错的决定是：**要不要显示完成百分比？**

「62%」看起来直观，但它被否掉了，理由有三条：

1. **进度不是线性的。** 学完后端这件事，你可能一个月没动静（在忙别的），然后三天做完一半。百分比会把这种正常起伏显示成「停滞」。
2. **百分比需要人填。** 一旦要你手动更新进度，这就变成了打卡——而设计里写得很清楚：打卡靠负罪感驱动，是这类项目头号死因。
3. **百分比不给证据。** 「62%」不能拿去面试，也不能在你想放弃时说服你。「给同学讲了 JWT 刷新」可以。

第二个决定：**`life goal done` 不校验证据。**
你说完成就是完成。系统只负责照实把分布摆出来（比如全是「接触」档，卡片上就写「以接触为主，缺少独立产出」）。判断权在你，因为只有你知道自己是真的会了，还是只是糊弄自己。

第三个决定：**在目标页上记的东西，`goal` 字段直接写死，不让模型猜。**
用户既然点进了「找到实习」再写字，这件事属于哪个目标是**已经说过的信息**，再让模型猜一遍只会出错（它可能写成「找工作」「实习」）。
这和「首页记一条」是两种情况：首页没有上下文，只能靠模型判断（猜不出就留空）。

**被否掉的替代方案**：让用户记完再去记录页手动「挂到某个目标」。
那要多点三次、要记住目标叫什么，而且大多数人不会回头挂——于是目标页永远是空的。
**归属信息应该在你写字的那一刻就带上，而不是事后补。**

第四个决定：**「问老师」只给它这个目标的证据。**
最省事的做法是把全部记录塞给它（`life ask` 就是这么干的）。但那会让它分不清两件事：
「这个目标卡住了」和「他这周在忙别的」——而这两种情况该给的建议完全相反。
只给这个目标的证据（几条、什么档、卡在哪），它才可能说出「你三条都是接触档，这周把它做成能给别人看的东西」。

**为什么还配三个一键问题？**
因为大多数人打开对话框时不知道该问什么，只会打「我该怎么办」。
把最常问的三句做成按钮，比让他先想出一个好问题容易得多——这也是「降低启动成本」的同一个思路。

**被否掉的替代方案**：
- 让它直接给一份「目标计划表」（几周、每周做什么）：那是模板，不是建议。他不知道的东西（每周有几小时、投过哪些公司）模型只能编。
- 让建议自动出现在页面上（一进页面就调模型）：等于每次看目标都花钱，而且大部分时候他说得对——他只想看看证据。

## 5. 已知限制

- **「问老师」只看这个目标**：它不知道你最近在忙别的、也不知道你有多累。要看全局，用「提问」那一页。
- **一次问答一次模型调用**（十来秒），没有流式输出；点了按钮就等，等不到会留在目标页说明原因。
- **对话不会自动总结**：聊三十轮它仍然只带最近 3 轮上下文，更早的留在文件里但模型看不到。
- **在首页（或命令行不带 `--goal`）记的记录，仍然靠 `entry.goal` 字段关联**。抽取时没认出目标（或者目标建好之前就记过了），那条记录就挂不上。
- **已经存在的记录没有「挂到某个目标」的按钮**，只能手改 markdown 里的 `goal:` 字段。这是下一步最值得补的缺口。
- 目标**不能挂子目标**（`parent` 字段写好了但还没有命令用它），三层结构要等以后。
- 没有「目标列表按进度排序」——因为根本没有进度这个数。
- `progress_mode: manual` 这个字段存在但没实现：现在只有 derived（从记录推）。
- 卡片里的「投入 ~11h」是把记录的 `minutes` 加起来，而 `minutes` 是抽取时估算的，不准。
- 在目标页记的一条如果被抽成多条（比如整份简历），**每一条都会挂到这个目标**——因为用户是在这个目标里传的。想拆开要自己改 `goal` 字段。

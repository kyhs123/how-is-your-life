# 目标（life goal）

## 1. 这个功能对用户是什么

你写下「想学完后端基础」，然后照常记事。过一阵回头看这个目标，它不会给你一个「完成 62%」的数字——那玩意儿是骗人的。

它给你的是**证据**：

```
## 学完后端基础    2026-09 → 现在
42 条记录 ｜ 投入 ~65h ｜ 最近 3 天活跃

证据分布
  能讲     1 条   给同学讲了 JWT 刷新
  产出     5 条   api-server（repo）、部署上线、N+1 优化
  复现    12 条
  接触    24 条

能拿出手的：
  · 给同学讲了 JWT 刷新（能讲）
  · 部署上线（产出）
```

看这张卡，你自己就知道「我是真的会了，还是只是在门口转」。面试官问「你会什么」的时候，你答的就是这张卡。

```powershell
life goal add "学完后端基础" --horizon term --why "想自己能做一个完整的网站"
life goal list
life goal show 1
life goal done 1
life goal stop 1 --reason "发现更想做前端"
```

## 2. 一次调用的完整路径

```
life goal add "学完后端基础" --horizon term --why "…"
  ↓
① 检查有没有重名目标（有就报错，不让立第二个一样的）
② 组装字段：id / title / horizon / why / started / due / status / progress_mode / parent
③ 写 vault/goals/学完后端基础.md（markdown + 开头那段键值）
④ 同时写进索引的 goals 表
  ↓
life goal show 1
  ↓
⑤ 从索引里取出全部非私密记录
⑥ 挑出 goal 字段指向这个目标的那些（这就是「证据」）
⑦ 按证据档分组数数、按档位举 2~3 个例子、算出总投入时间
⑧ 渲染成文字卡片
```

```
vault/goals/<标题>.md ──┐
                        ├─→ goal.算证据() ─→ 一张卡片（纯文字）
索引里的全部记录 ────────┘   （按 entry.goal 字段关联）
```

## 3. 关键代码在哪

```
life/goal.py::建目标()      立目标（查重 + 写文件 + 写索引）
life/goal.py::找目标()      按编号/名字/前缀找，省得你打全名
life/goal.py::关联条目()    哪些记录算这个目标的证据
life/goal.py::算证据()      数条数、数档位、算时长
life/goal.py::渲染卡片()    输出那张卡
life/goal.py::改状态()      done / stop（stop 会把原因写进文件）
life/cli.py::goal_add/list/show/done/stop   命令本身
```

## 4. 为什么这么设计

最容易被做错的决定是：**要不要显示完成百分比？**

「62%」看起来直观，但它被否掉了，理由有三条：

1. **进度不是线性的。** 学完后端这件事，你可能一个月没动静（在忙别的），然后三天做完一半。百分比会把这种正常起伏显示成「停滞」。
2. **百分比需要人填。** 一旦要你手动更新进度，这就变成了打卡——而设计里写得很清楚：打卡靠负罪感驱动，是这类项目头号死因。
3. **百分比不给证据。** 「62%」不能拿去面试，也不能在你想放弃时说服你。「给同学讲了 JWT 刷新」可以。

第二个决定：**`life goal done` 不校验证据。**
你说完成就是完成。系统只负责照实把分布摆出来（比如全是「接触」档，卡片上就写「以接触为主，缺少独立产出」）。判断权在你，因为只有你知道自己是真的会了，还是只是糊弄自己。

## 5. 已知限制

- **记录和目标靠 `entry.goal` 字段关联**。抽取时没认出目标（或者目标建好之前就记过了），那条记录就挂不上。现在没有「手动把某条记录挂到某个目标」的功能，只能手改 markdown 里的 `goal:` 字段。
- 目标**不能挂子目标**（`parent` 字段写好了但还没有命令用它），三层结构要等以后。
- 没有「目标列表按进度排序」——因为根本没有进度这个数。
- `progress_mode: manual` 这个字段存在但没实现：现在只有 derived（从记录推）。
- 卡片里的「投入 ~11h」是把记录的 `minutes` 加起来，而 `minutes` 是抽取时估算的，不准。

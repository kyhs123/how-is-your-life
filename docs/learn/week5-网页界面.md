# 第 5 周：本机网页界面

## 1. 这周做了什么

在浏览器里点几下就能改目标、确认记录——但这个页面只有我自己的电脑能打开。

## 2. 这些知识在真实世界里用在哪

**场景一：所有「内部工具」**。运营同事改一条配置、客服查一个订单，背后都是一个只在内网能访问的小网页。你这周写的就是它的最小版：路由 + 表单 + 写库。

**场景二：所有需要「防重复提交」的地方**。用户点两下「付款」，不该付两次。这周学的 **POST 之后跳转（PRG）** 和**一次性令牌**，是所有表单系统的标配。

## 3. 出现的名词，大白话解释

| 术语 | 一句话解释 | 在本项目里指什么 |
|---|---|---|
| HTTP 方法 | GET 是「我要看」，POST 是「我要改」 | 看页面用 GET，提交表单用 POST |
| 路由 | 网址 → 处理函数的对应表 | `/goal/new`、`/entry/<id>/settle` |
| 表单编码 | 浏览器把输入框打包成 `键=值&键=值` | `urllib.parse.parse_qs` 拆它 |
| CSRF | 别的网站偷偷替你的浏览器提交表单 | 用一次性令牌 + 校验 Origin 挡掉 |
| DNS rebinding | 别人的域名解析到 127.0.0.1，骗浏览器去打你的本机服务 | 校验 Host 头挡掉 |
| PRG | POST 之后立刻 303 跳转 | 防止刷新导致重复提交 |
| 回环地址 | 127.0.0.1，只有本机能连 | 服务器只绑它 |
| 转义 | 把 `<` 换成 `&lt;` 再放进网页 | 用户写的内容不能直接拼进 HTML |

## 4. 三个「为什么这么设计」

**① 为什么不用 Flask / FastAPI？**
否掉的方案：装个框架，写 CRUD 更快。但这里只有三个动作、只服务一个人、只在本机跑几分钟。用框架要背它的一整套概念（蓝图、依赖注入、ASGI），而标准库 `http.server` 一百行就够。**工具要对得上问题的规模。**

**② 为什么本地工具还要做安全检查？**
否掉的方案：「反正只有我能访问」。但浏览器不这么想——你打开的任何网页都能向 `127.0.0.1:8770` 发请求。没有令牌和 Host 校验，一个恶意网页就能改你的目标。**「只在本机」不等于「只有本机能调用」。**

**③ 为什么第一版只做两件事？**
否掉的方案：一次做全，能改正文、能删记录、能批量。但写操作改的是真实人生记录，出错代价远高于只读。先只做改元信息（目标、状态），把风险控制在「改错了还能再改回来」的范围内。

## 5. 你可以自己动手试的一件事

```powershell
.\.venv\Scripts\life.exe server --open
```

页面打开后，先用浏览器**换个地址**访问一次：把网址改成 `http://localhost:8770/`——如果打不开，就是因为只绑了 IPv4 回环。

然后打开开发者工具（F12）→ 网络，点一下「确认」按钮，看那个 POST 请求返回的 **303**，以及浏览器紧接着又发了一次 GET。这就是 PRG。

## 6. 面试官问起这周的东西，你可以这么答

**S**：给一个本地人生记录工具做可编辑的界面，之前只能看不能改。

**T**：难点不是画页面，是**只在本机跑的服务怎么防住浏览器里的攻击**，以及写操作怎么不把用户的数据改坏。

**A**：我用标准库 `http.server` 起一个只绑 `127.0.0.1` 的服务，加了三道校验（Host 防 DNS rebinding、Origin + 一次性令牌防 CSRF、所有输出转义），POST 一律 303 跳转防重复提交；范围上只做「改目标」和「确认记录」两件事，不碰记录正文。

**R**：7 个测试都是真起服务器、真发 HTTP 请求、真看磁盘上文件变没变；实测外部 Host 返回 403，中文令牌不会再让连接崩掉（`compare_digest` 不支持非 ASCII，改成比字节）。

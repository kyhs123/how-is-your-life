# 第 1 周：录入与抽取

## 1. 这周做了什么

让程序能接住我随手写下的一句话，压成三个月后还看得懂的一行，存成我自己随时能打开的文件。

## 2. 这些知识在真实世界里用在哪

**场景一：任何「先存下来、再处理」的地方。** 你以后做的每个网站都会遇到——用户点了「提交订单」，你必须先把订单写进数据库，再去发短信、发邮件。反过来的话，发短信那一步崩了，用户填的东西就全没了。这周学的就是这条顺序为什么要反过来。

**场景二：任何让 AI 返回结构化数据的地方。** 所有接大模型的系统都会撞上「它偶尔多回一句人话，我的程序就解析失败」。处理办法就是你这次学的那套：先约束格式，再校验，失败重试一次，最后兜底不丢。换个业务、换家模型，这套骨架都不用变。

## 3. 出现的名词，大白话解释

| 术语 | 一句话解释 | 在本项目里指什么 |
|---|---|---|
| markdown | 用纯文字加几个符号排版的文件 | 每条记录就是一个 `.md` 文件，记事本能开 |
| 落盘 | 真的写进硬盘，不是先放内存里等着 | `life add` 第二步就把原话写进 inbox |
| front-matter | 文件开头用 `---` 包起来的一段「键: 值」 | `did`、`level` 这些字段住在这里 |
| 抽取 | 让 AI 把口语压成一行带细节的短句 | 一条记录（entry）的诞生过程 |
| 锚点 | 具体到编不出来的细节：技术名、报错、数字、链接 | 判断记录合不合格的唯一标准 |
| 结构化输出 | 让接口按你给的字段表返回，不许自由发挥 | `llm.py` 里三级降级的第一级 |
| 幂等 | 同样的内容提交两遍，结果还是只有一条 | 靠内容指纹判断「这条记过了」 |
| 指纹（哈希） | 把任意内容算成一串固定长度的字符 | sha256，用来认「是不是同一条」 |
| 索引 | 数据库里的目录页，专门用来快速找 | `index.sqlite`，删了能重建 |
| 虚拟环境 | 给这个项目单独一套依赖，不污染系统 | `.venv` 目录 |

## 4. 三个「为什么这么设计」

**① 为什么先落盘再抽取？**
否掉的方案是「先调 AI，拿到结果再写文件」——省事。但它断网就丢、超时就丢、AI 返回不合格也丢。记录产品里丢一条的代价远大于多一条待办，所以顺序必须反过来：先让这件事成为硬盘上的事实，再谈加工。

**② 为什么 markdown 当真相源、数据库只当目录？**
否掉的方案是「只存数据库」，更快、代码更少。但那样你没法用记事本看自己的记录，改一个字要写代码，数据库打不开的那天记录就永久锁死。所以规则是：正文在 markdown，数据库随时可删可重建。

**③ 为什么不直接写「请输出 JSON」？**
否掉两个方案：一是用正则从自然语言里抠字段（模型换个说法就崩）；二是完全相信模型（漏字段时下游全错，而且你不知道错在哪）。现在用的是接口层面的 schema 约束 + 客户端逐字段校验 + 把错误回喂重试一次，两次都不行就标 `needs_review` 留给人看，绝不静默丢弃。

## 5. 你可以自己动手试的一件事

```powershell
.\.venv\Scripts\life.exe add "今天读完了两章 Docker 文档" --demo
```

然后用记事本打开 `vault/now/2026-11/` 里新出现的那个 `.md` 文件。接着**故意把开头那行 `---` 删掉**，再跑：

```powershell
.\.venv\Scripts\life.exe reindex
```

它会告诉你哪个文件读不进来，而其它记录照常建好索引——这就是「一条坏数据不该拖垮整个系统」。

## 6. 面试官问起这周的东西，你可以这么答

**S**：我要做一个本地运行的人生记录工具，第一周只有录入、抽取、索引三件事。

**T**：难点有两个——断网时用户写的话一条都不能丢；AI 返回的东西要能直接进数据库。

**A**：我把录入拆成「先落盘、再抽取」，用内容指纹做幂等；AI 那边做 json_schema → json_object → 纯文本三级降级，加客户端校验和一次重试，两次失败标 `needs_review` 而不是丢掉。

**R**：37 个测试覆盖了断网、重复提交、坏文件、private 不外发；索引删掉后能从 markdown 完整重建。真模型联调时还抓出两个坑——模型返回空列表会吞掉原话、空输入会让它凭空编一条，都改成了兜底保存。

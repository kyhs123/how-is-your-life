# 第 4 周：画像与回顾

## 1. 这周做了什么

让它每季度给我写几条**关于我自己的猜测**（不是判决），每周给我一份回顾——而且没网也出得来。

## 2. 这些知识在真实世界里用在哪

**场景一：所有「AI 生成报告」的产品**（周报助手、体检报告解读、财报摘要）。行业里通用的分工是：**数字由代码算，人话由模型写**。原因很简单——模型算错一个数你就再也不信整份报告，而它会算错。这周写的就是这个分工。

**场景二：所有要生成「给人看的文件」的地方**（发票、对账单、导出 PDF）。都要面对同一个问题：样式怎么保证在哪台机器上都一样。答案是**自包含**：CSS 内联、图片转成矢量、不引外部链接。

## 3. 出现的名词，大白话解释

| 术语 | 一句话解释 | 在本项目里指什么 |
|---|---|---|
| 画像 | 对你是个什么样的人的**假设清单** | `vault/portrait/2026-Q4.md` |
| 巴纳姆效应 | 「你有时外向有时内向」这种谁都适用的鬼话 | 画像里必须避免的东西 |
| diff | 和上一版比，改了什么 | 画像里带删除线的那一块 |
| 自包含 HTML | 一个文件装下所有样式和图，不联网也能看 | `life review --html` 的产物 |
| 降级 | 某个依赖坏了，功能打折但还能用 | 模型挂了，回顾仍然出数据 |
| max_tokens | 一次回答最多能生成多少 token | 思考型模型会把它全花在「想」上 |

## 4. 三个「为什么这么设计」

**① 为什么画像写假设，不写结论？**
否掉的方案：直接输出「你是一个内向、缺乏自信的人」。两个理由——固定标签必然滑向巴纳姆效应；而且**能承认「我上次猜错了」的系统更可信**。所以硬性要求每条假设带「依据：N 次」，旧假设用删除线留着。

**② 为什么数据全由代码数，只有一段话交给模型？**
否掉的方案：把记录丢给模型，让它自己算「这周几条、分布如何」。它会算错，而错一个数，整份回顾就不可信。所以条数、分布、平均情绪全用 SQL 数，模型只写「这段日子怎么过的」。

**③ 为什么模型挂了回顾也要出得来？**
回顾是低频动作。断网就什么都看不到的话，用户下次就不跑了。所以模型失败只降级掉那段话——**能自己算出来的，绝不依赖网络**。这和录入的「先落盘」是同一个思路。

## 5. 你可以自己动手试的一件事

```powershell
$env:LIFE_HOME = "$PWD\试试"     # 换个地方，不碰你自己的 vault
.\.venv\Scripts\life.exe demo      # 灌入虚构的半年数据
.\.venv\Scripts\life.exe goal show 1
.\.venv\Scripts\life.exe review --quarter --html --out 回顾.html
start 回顾.html
```

打开那份 HTML，然后**断网再刷新一次**——它照样显示。这就是「自包含」的意思。

## 6. 面试官问起这周的东西，你可以这么答

**S**：给一个记录工具做季度画像和周回顾。

**T**：两件事不能错——画像不能变成贴标签，回顾的数字不能错。

**A**：画像强制「写假设 + 每条带依据 + 旧假设用删除线保留」，并且用代码检查哪条没写依据；回顾把「算数」和「说话」拆开，数字全用 SQL，模型只写一段叙述，模型挂了就降级成纯数据；输出 HTML 是自包含单文件，不引任何外链。

**R**：联调时抓到一个真问题——思考型模型把 2000 token 全花在推理上，正文一个字都没出（finish_reason=length）。加上 `max_tokens` 和超时按任务可配，并把这个情况变成一句看得懂的报错，而不是留一个空文件。

# 网页界面设计（WEBUI）

> 这份文档是 `life server` 的**施工图**。写完它之后，页面的每一个区块、每一个按钮、
> 每一条拒绝理由，都必须能在本文里找到依据。**改动先改这里。**
>
> 上层约束仍然以 `docs/DESIGN.md` 为准；本文只负责把它落到一个具体的界面上。

---

## §0 这份界面要解决什么

设计 §2.1 说这个产品有三个视角（不是三个模块，是同一份数据的三个看法）：

| 视角 | 回答的问题 | 对应数据 |
|---|---|---|
| **人生记录** | 我会什么？我做过什么？ | `entry`（`part=record`） |
| **人生规划** | 我现在该干什么？ | `goal` |
| **情感记录** | 我为什么难受？我是谁？ | `entry`（`part=emotion`）+ `portrait` |

第 5 周的第一版只做了「人生规划」，把**最高频、最核心的「记一条」漏在外面**——这是设计上的错，本文纠正它。

**一句话定位**：这是一个「每天打开一次、十秒钟记一句话、想不开的时候翻旧账」的本机页面。
不是后台管理系统，不是数据看板。

## §1 硬约束（不可违反，来自 DESIGN.md 与 AGENTS.md）

| # | 约束 | 在界面上的体现 |
|---|---|---|
| W1 | 只绑 `127.0.0.1` | 局域网里的手机/别的电脑连不上。想看就坐在那台电脑前 |
| W2 | 不引入前端框架、不用 JS 框架、不用构建工具 | 服务端渲染 + 原生表单 + PRG。**零外部资源**（无 CDN、无字体、无图标库） |
| W3 | 真相源是 markdown | 页面上的每一次写操作，**改的都是 `vault/` 里的 `.md` 文件**；索引跟着重建。没有「页面自己的数据库」 |
| W4 | 私密记录不参与任何"翻出来"的动作 | `--private` 的记录不出现在提问、画像、回顾、提名的材料里；但**在页面上可见并标注**（那是你自己的电脑） |
| W5 | 不做 KPI 面板、不标红未完成、不催进度、不算连续天数、不显示百分比 | 目标卡片只写事实：多少条记录、各档几条、拿得出手的是什么 |
| W6 | 写操作必须经过和命令行**同一批函数** | `recorder.记录一条` / `store.改条目状态` / `goal.更新目标` / `promote.确认`。页面里不写第二套写盘逻辑 |
| W7 | 断网也能记 | `/add` 先落盘再抽取；抽取失败时页面明确说「已经存好了」 |
| W8 | 不存图片原图 | 上传的图片和文件走同一条「先落盘、再处理」的链路；处理后**原文件默认删掉**，只留全文（`vault/media/<id>.md`）；勾「保留原文件」才留下（见 §2.4） |

## §2 信息架构

### §2.1 导航（每页顶部固定）

```
你过得怎么样    今天 · 记录 · 提问 · 目标 · 主题 · 画像 · 设置
```

「今天」永远在最左，因为它是默认动作。

**两条定名规矩（2026-11-26 按用户反馈改的）：**

1. **导航上一个词都不该需要解释。** 原来叫「章节」的那一栏现在叫「**主题**」——
   用户的原话是*「章节是什么意思？」*。代码里还叫 chapter（内部词汇无所谓），
   但页面上必须是他一看就懂的话，而且页面开头要写清它和目标什么区别。
2. **能从别处问出来的，不单独占一栏。** 原来的「回顾」页删掉了——
   想知道最近一周做了什么，直接在「提问」里问「我这周都做了什么」就够
   （为此 `life ask` 补了按时间段检索，见 `docs/features/检索.md`）。
   `life review` 这条命令还在：季度回顾要的是一个能存下来的文件，那件事网页上做不如命令行做。

### §2.2 页面清单

| 路由 | 页面 | 干什么 | 阶段 |
|---|---|---|---|
| `/` | **今天** | 记一条（主表单）+ 最近 7 天的记录流 + 待确认计数 | M0 |
| `/entries` | **记录** | 全部记录，按月分组，可按 `part`/`level` 筛选，分页 | M1 |
| `/entries/<id>` | **单条** | 看一条的全部字段 + 改 `did`/`level`/`outcome`/`status` | M1 |
| `/ask` | **提问** | 输一句话 → 三路召回 + 模型回答（同步等 5~20 秒）。问「这周做了什么」也走这里 | M2 |
| `/goals` | **目标** | 目标列表 + 新建入口 | M0 |
| `/goals/new` | 新建目标 | 一张表单 | M0 |
| `/goals/<id>` | 目标详情 | **证据卡**（档位分布、拿得出手的、还缺什么）+ **这个目标自己的记一条**（自动带上 `goal`，记完回本页）+ 改目标入口 | M0 |
| `/chapters` | **主题** | 归纳出来的主题列表（同一件事的记录串成一条线）+ 每条的记录数/最高档 | M2 |
| `/chapters/<id>` | 主题详情 | 摘要 + 它名下的记录 | M2 |
| `/portrait` | **画像** | 展示最近一份季度画像（只读）+ 一句「怎么重新生成」 | M2 |
| `/settings` | **设置** | vault 路径、模型名、条数统计、端口；只读，不给改配置 | M2 |

### §2.3 写操作清单（允许 / 不允许）

| 允许 | 走哪个函数 | 说明 |
|---|---|---|
| 记一条（纯文字） | `recorder.记录一条` | 含「情感」「私密」两个勾选 |
| **记一条（图片）** | `recorder.记录一条(图片=…)` | 和 `life add --image` 同一条链路：视觉模型一次调用 → OCR 全文 + 摘要 + claims |
| **记一条（文档）** | `recorder.记录一条(文档=…)` | 本地抽文本（`.txt` `.md` `.docx`），再走文本抽取 |
| 确认一条待确认记录 | `store.改条目状态` | `needs_review` → `settled` |
| 改一条记录的 `did`/`level`/`outcome`/`status` | `store.改条目字段` | 会校验取值范围和 60 字上限 |
| 新建 / 修改目标 | `goal.建目标` / `goal.更新目标` | |
| 拒绝 / 确认晋升提名 | `promote.拒绝` / `promote.确认` | |

| 不允许（第一版） | 为什么 |
|---|---|
| **删除记录** | 设计里没有「删除」这个概念，人生记录不该有一个「一键抹掉」。要删请直接删 `.md` 文件——那需要你明确地做一件事 |
| 批量操作 | 一次改很多条的代价太高，错一次就是一片 |
| 编辑正文（markdown 正文段） | 正文目前等于 `did`，改 `did` 就够了 |
| 富文本 / 拖拽 | 记忆不需要排版 |
| **PDF / 压缩包 / 音视频** | 需要额外解析库（PyPDF、解压黑名单、音频转写），MVP 不做。上传这类文件会明确告诉你「不支持」而不是悄悄失败 |
| — | （原先不允许在页面上跑长任务，已改为后台任务，见 §2.6） |

### §2.6 后台任务（让长任务也能点按钮）

**问题**：`portrait` / `settle` 要调模型 30 秒~3 分钟。同步等 → 浏览器转圈、容易超时、看着像卡死。

**做法**：点按钮 → 起一个后台线程 → 立刻跳到任务页 → 任务页用 `<meta http-equiv="refresh" content="3">` 每 3 秒自刷 → 完成就显示结果和「去看起来」的链接。

| 项 | 规则 |
|---|---|
| 任务表 | 存在内存里（进程重启就没了，这是本机小工具，够用） |
| 同类只能一个 | 同一个动作正在跑时，再点按钮不会叠加，直接进正在跑的那个任务页 |
| 失败怎么办 | 任务页用红字显示原因，并给出「重试」按钮 |
| 不引入 JS | 用 `<meta refresh>` 自刷；不做进度百分比（不知道进度就不要假装知道） |
| 支持的动作 | `portrait`（生成画像）、`settle`（归纳主题、写提名）、`reindex`（重建索引）、`retry`（补抽没抽成的记录）、`tidy`（瘦身） |

**为什么不做「实时进度条」**：模型调用没有可靠的进度回调，编一个假的百分比比转圈更糟。所以只显示「正在跑，已经 X 秒」，跑完给结果。

| 页面 | 按钮 |
|---|---|
| 画像 | 生成 / 重新生成本季度画像 |
| 主题 | 归纳最近的记录（写提名）；以及**每条提名的「要 / 不要」按钮** |
| 设置 | 重建索引、瘦身（清 90 天前的缓存 + 孤儿全文） |
| 今天 | 有没抽成的记录时，出现「补抽」按钮 |

**晋升仍然不自动**：`settle` 只写提名，页面上的「要 / 不要」仍然要你点。这条不变。

### §2.4 上传规则（图片与文件）

| 类型 | 允许的扩展名 | 内容校验 | 大小上限 | 怎么处理 | 最后留下什么 |
|---|---|---|---|---|---|
| 图片 | `.png` `.jpg` `.jpeg` `.webp` `.gif` | **看文件头魔数**（PNG `\x89PNG`、JPEG `\xFF\xD8`、GIF `GIF8`、WebP `RIFF….WEBP`） | 8 MB | 一次视觉模型调用 → `ocr_text` 全文 + `digest` + `claims` | `vault/media/<id>.md`（OCR 全文 + 摘要）；原图**删掉**，勾「保留原文件」才留 |
| 文档 | `.txt` `.md` `.docx` | `.docx` 必须是含 `word/document.xml` 的 zip | 8 MB | 本地抽文本（`zipfile` + 剥 XML 标签，不引第三方库）；送模型的部分最多 20000 字，全文另存 | `vault/media/<id>.md`（全文）；原文件**删掉**，勾选才留 |
| 其它 | — | — | — | 拒绝，并说明支持哪些 | 什么都不留 |

**四条硬规矩**

1. **先落盘再处理**（W7）：文件先落到 `vault/inbox/文件暂存/`，然后才谈抽取。抽取失败，文件仍在。
2. **文件名不可信**：只取扩展名判断类型，落盘名用记录 id（`20261125-193000.png`），**永远不用用户给的文件名拼路径**。
3. **抽不出文本就说抽不出**：`.docx` 解析失败、编码不是 UTF-8、全文为空 → 明确报错，而不是存一条空记录。
4. **全文一定留**：原文件删掉之后，`vault/media/<id>.md` 是它唯一的「原话」——这就是 §5.5「OCR 必须是全文」的同一道理。

### §2.5 「什么时候」——记一条多一个可选字段，不是单独模块

**这不是一个新功能。** 人生记录本来就包含之前的人生：大一做的项目、去年那场面试，都是你的人生。
把它做成「导入模块」是错的——那等于暗示「现在记的」和「以前发生的」是两种东西。

所以：**「记一条」多一个可选字段 `什么时候`**，网页上是表单里的一行输入，命令行是 `life add --when`。

**日期可以不填，也可以写得含糊。** 简历要的是「你做过这个、你会这个」——不是精确到哪一天。

| 你填的 | 时间戳（程序用） | `when`（人看） | 页面显示 |
|---|---|---|---|
| 不填 | 现在 | `""` | 今天的日期 |
| `2023-09-15` | 2023-09-15 12:00 | `2023-09-15` | `2023-09-15` |
| `2023-09`（只知道月） | 2023-09-01 12:00 | `2023-09` | **`2023-09`**，并提示「只知道月份，时间戳记为 …」 |
| `2023`（只知道年） | 2023-01-01 12:00 | `2023` | `2023` |
| `大一` / `记不清了` | **录入时刻** | 原话 | **`大一`**，并提示「时间不详」 |
| 未来的日期 | — | — | 拒绝：「不能补记未来的事」 |

**为什么不硬凑一个日期**：把「大一的三个项目」都写成 `2023-01-01`，等于让数据说谎。
`when` 存你说的原话，`ts` 存能给程序用的时间；两者谁都不冒充谁。

**落盘位置**：和普通记录完全一样，`vault/now/YYYY-MM/`。分层按证据走，不按文件位置走。

**和简历的关系**：后面要做的 STAR 卡（`docs/DESIGN.md` §10.2「面试模式」）要从这些记录里挑素材——
**素材越全越好，日期越准越好，但不准也必须能记。** 这一条决定了「补记」只能是可选字段，不能是必填门槛。

**一件事**：补记进来的旧记录，`settle` 默认那 7 天窗口是看不到的，要固化请给范围：
`life settle --since 2023-01`。

**不做**：逐条指定日期、CSV 批量导入、从旧博客自动抓取。

- 主表单必须在**首屏**，不需要滚动就能写。
- 文字和文件**至少给一个**：只写字、只传文件、或两个都给（文件当素材、文字当说明）。
- 「待确认」只在有东西时出现，用一句话 + 链接，不占地方。
- 最近七天只显示 `did` + 日期 + 档位，想看全部点「记录」。

### §3.2 记录（`/entries`）

```
筛选： [全部] [做过什么] [想去哪] [感受]   档位：[全部] [接触][复现][产出][能讲]
─────────────────────────────────────────────────
2026-11  (12 条)
  11-25 · 产出 · 接通 OAuth，卡点为…            → 点开
  11-24 · 能讲 · 给同学讲了 JWT 刷新            → 点开
2026-10  (8 条)
  …
[ 更早 ]
```

- 按月分组（和看板一致），月内新的在上。
- 每页 50 条，底部「更早／更新」。
- 私密记录显示一个「私密」小标。

### §3.3 单条（`/entries/<id>`）

```
2026-11-25 19:20 · 产出 · settled
接通 OAuth，卡点为 state 参数签名
锚点：OAuth / state 参数      卡点：state 参数要签名
原话：「文档写得跟屎一样」     情绪：-0.5

── 改这一条 ──
did      [______________________________]  (≤60 字)
档位     [接触|复现|产出|能讲]
结果     [做完|卡住|放弃]
状态     [待处理|已定稿|待确认]
[ 保存 ]   [ 算了 ]
```

- 只读部分展示全部字段（含锚点、卡点、原话、情绪）。
- 可改的只有四个：`did`、`level`、`outcome`、`status`。**不提供**改 `private`（那会改变隐私承诺，容易误操作）。

## §4 视觉与样式系统

一套变量，一处 `<style>`，所有页面共用（不引外部资源）。

```css
:root{
  --纸:#faf8f4; --墨:#22201d; --淡:#7b746c; --线:#e2ddd4; --卡:#fffdf9;
  --点:#7d9b76;   /* 主色，用于按钮和强调 */
  --坏:#b5544a;   /* 只用于「错误」和「私密」标记，不用于「未完成」 */
}
@media (prefers-color-scheme: dark){ /* 深色一套 */ }
```

| 组件 | 规则 |
|---|---|
| 卡片 | 白底、1px 边线、左侧 3px 色条（记录用绿、私密用红） |
| 按钮 | 主按钮实心点色；次按钮描边；**不用红色按钮**（红色只做提示，不做「危险操作」的强调） |
| 徽章 | 档位四色（接触灰、复现浅绿、产出绿、能讲深绿）；`needs_review` 用一条细边框，不用红色 |
| 表单 | `label` 包住 `input`，点击文字也能聚焦；输入框 8px 内边距、圆角 6px |
| 空状态 | 一句话说「这里还没有东西」+ 一个下一步动作 |
| 错误 | 页面顶部 inline 提示，红字，不弹窗 |

**响应式**：`max-width: 720px` 居中，窄屏自动单列。手机上打开 `127.0.0.1` 打不到——这是 W1，不是 bug。

**无障碍**：语义标签（`header/nav/main/section/article`）、`label` 关联、明显的 `:focus` 轮廓、正文对比度 ≥ 4.5:1。

**JS**：只允许一处——`textarea` 里按 `Ctrl+Enter` 提交。三行内联，失败也不影响使用。

## §5 服务端设计

### §5.1 技术选择

| 选择 | 理由 |
|---|---|
| 标准库 `http.server` + `ThreadingHTTPServer` | 零依赖；`/ask` 要等模型，必须能并发（否则一个人等回答时另一个人打不开页面） |
| 服务端渲染（f-string 拼 HTML） | 和看板/回顾同一套路；改样式只需改一处 |
| 原生表单 + PRG（POST → 303 → GET） | 刷新不会重复提交 |
| 无数据库 | 读走索引（可重建），写走 markdown |

### §5.2 模块划分

```
life/server.py    传输层：绑定、路由、表单解析、三道安全校验、状态码
life/pages.py     渲染层：每个页面一个纯函数（数据进、HTML 出），不碰磁盘
life/recorder.py  写入层：记一条（CLI 和网页共用）
life/store.py     数据层：条目的读 / 改字段 / 改状态
life/goal.py      目标
life/promote.py   晋升（网页只用「确认/拒绝」）
```

**一条硬规矩**：`pages.py` 里不许出现 `write`、`open`、`sqlite`。它只接收准备好的数据。

### §5.3 路由表

| 方法 | 路径 | 动作 |
|---|---|---|
| GET | `/` | 今天 |

### §5.4 安全（四条，缺一不可）

1. **绑地址**：`HTTPServer(("127.0.0.1", 端口))`。
2. **Host 校验**：只接受 `127.0.0.1:<端口>` / `localhost:<端口>`。挡 DNS rebinding。
3. **CSRF**：进程启动时生成一次性令牌，每个表单带隐藏字段 + 页面 `<meta>`；POST 校验令牌（比较 UTF-8 字节，`compare_digest` 不支持非 ASCII 字符串）。同时校验 `Origin`/`Referer` 前缀。
4. **转义**：所有用户内容过 `html.escape`；`id` 只允许 `[0-9A-Za-z_\-\u4e00-\u9fff]`，拒绝 `/`、`..`、空串（挡路径穿越）。
5. **上传四限**：整体请求体 ≤ 12MB；单个文件 ≤ 8MB；只按扩展名 + **魔数** 判断类型；落盘文件名一律用记录 id，绝不用上传时的文件名（挡路径穿越和同名覆盖）。
6. **multipart 自己解析**：标准库没有现成实现。规则：只认 `Content-Disposition: form-data`、忽略空段、每个 part 的头部总长 ≤ 8KB、字段值 ≤ 1MB。解析失败就说「上传的内容看不懂」，不做任何猜测。

### §5.5 错误处理

| 情况 | 页面 | 状态码 |
|---|---|---|
| 找不到记录/目标/主题 | 友好页 + 「回今天」 | 404 |
| 字段不合法（档位越界、`did` 超 60 字） | 回到那张表单，红字说明，**保留已填内容** | 400 |
| 令牌 / Host / Origin 不对 | 「拒绝了」+ 原因 | 403 |
| 抽取失败但已落盘 | 今天是 200 + 顶部提示「已存好，抽取失败，稍后 life retry」 | 200 |
| 未捕获异常 | 「服务器内部出错了」+ 简短原因，不泄露堆栈 | 500 |

### §5.6 性能

- 记录列表每页 50 条，按月分组；不一次加载全部。
- **抽取缓存按内容指纹前两位分 256 个桶**（`缓存/抽取/ab/….json`）——不然五年后九千个文件挤在一个目录里。
- 每次请求现开现关一个 SQLite 连接（几千条的量级足够）。
- `/ask` 会有 5~20 秒等待：提交后浏览器转圈，页面顶部提示「正在翻你的记录…」。
